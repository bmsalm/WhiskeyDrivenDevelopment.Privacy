# Repository instructions

- Submit all content/configuration changes through a feature PR targeting main.
  Leave PRs open unless the owner explicitly authorizes merging.
- Keep this a static legal-information page: plain HTML/CSS, no frameworks,
  JavaScript, trackers, forms, externally loaded fonts or embedded payments.
- Verify every privacy claim against the current shipping app and dependencies.
  Never invent a contact address, policy approval, live URL or store certification.
- Keep developer/app identity, contact details, retention/deletion practices and
  last-updated date accurate. Distinguish app data practices from host/browser logs.
- Keep wording synchronized with the app's offline privacy notice and Play
  declarations. A code review or policy page does not guarantee Play approval.
- Preserve existing DNS and email settings. Configure/verify the GitHub custom
  domain before creating GoDaddy CNAME records; never use wildcard DNS.
- Obtain explicit owner approval before publishing a draft policy. Do not enable
  Pages, merge, or change DNS solely because a PR exists.
- Check mobile/desktop readability, keyboard link focus, light/dark appearance,
  valid HTML and no unexpected external resources before publishing.
